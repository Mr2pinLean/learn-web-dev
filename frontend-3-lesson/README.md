# ÉLAIRE — страница выбора услуг на React

Учебный пример: одна страница сайта салона красоты, написанная на React.
Только выбор услуг. Без сервера, без переходов, без других экранов.
Данные захардкожены внутри компонента `App`.

Используется на лекции, чтобы показать базовые приёмы React:
`useState`, пропсы, разбивку на компоненты, рендер списков через `map`.

---

## Как запустить

Нужен **Node.js** версии 18 или выше и **npm**.

```bash
node --version
npm --version
```

Если команды не найдены — установите Node.js с [nodejs.org](https://nodejs.org).

Дальше:

```bash
npm install     # установить зависимости (один раз)
npm run dev     # запустить dev-сервер
```

Vite напишет адрес — обычно `http://localhost:3000`.
Откройте его в браузере.

Другие команды:

```bash
npm run build     # собрать продакшн-версию в dist/
npm run preview   # посмотреть собранную версию
```

## Что внутри

Одна страница: слева список категорий, справа — услуги выбранной
категории. Сверху индикатор шагов бронирования, снизу — подвал.

Что работает:

- **Клик по категории в сайдбаре** — категория подсвечивается,
  справа появляется список её услуг.
- **Индикатор шагов** — показывает три шага бронирования,
  активен первый.
- **Форма, кнопки и переходы — не работают.** Это статичный пример
  только вёрстки и выбора категории.

│   └── LoadingState.jsx       # заглушки (LoadingState, EmptyState)
│
├── App.jsx                    # корневой компонент: состояние и данные
├── main.jsx                   # точка входа

Один компонент — один файл. `Header`, `Footer`, `Sidebar` — без
своего состояния. `App` — хранит `activeCategoryId`, от которого
зависит всё остальное.

## Как устроен код

### Состояние — только в `App`

В `App.jsx` есть один `useState`:

```jsx
const [activeCategoryId, setActiveCategoryId] = useState(100);
```

`activeCategoryId` — id выбранной категории. Всё остальное —
производные данные. По нему находим саму категорию и её услуги:

```jsx
const activeCategory = servicesData.find((cat) => cat.id === activeCategoryId);
const services = activeCategory ? activeCategory.services : [];
```

Когда пользователь кликает по категории, `activeCategoryId` меняется —
и React автоматически перерисовывает всё, что от него зависит.

### Данные идут вниз через пропсы

- `App` → `Sidebar` передаёт `categories`, `activeCategoryId`, `onCategoryClick`.
- `Sidebar` → `CategoryItem` передаёт `category`, `isActive`, `servicesCount`, `onClick`.
- `App` → `ServicesList` передаёт `services`.

Каждый компонент знает только про то, что ему нужно. `CategoryItem`
не знает, откуда взялись категории. `ServicesList` не знает, кто выбрал
категорию. Всё решает `App`.

### События идут вверх через колбэки

Пользователь кликает по категории в `CategoryItem`. Что происходит:

1. `CategoryItem` вызывает `onClick()`.
2. `Sidebar` вызывает `onCategoryClick(category.id)`.
3. `App` вызывает `handleCategoryClick(categoryId)`.
4. `handleCategoryClick` делает `setActiveCategoryId(categoryId)`.
5. React перерисовывает дерево — новая категория становится активной,
   `ServicesList` получает новые услуги.

Это называется «колбэки вверх». Дочерние компоненты не хранят состояние —
они сообщают наверх, что что-то произошло.

### Списки через `map`

Везде, где рендерится список, используется `.map()`:

```jsx
{categories.map((category) => (
  <CategoryItem key={category.id} category={category} ... />
))}
```

Обязательно с `key`. React использует ключ, чтобы понять, какие элементы
остались теми же при перерисовке. Берите `id`, а не индекс массива.

## На что смотреть в компонентах

### `App.jsx`

Здесь самое важное:

- массив `servicesData` — все данные страницы;
- `useState` для `activeCategoryId`;
- поиск активной категории через `.find`;
- обработчик `handleCategoryClick`;
- композиция — `<Header />`, `<main>`, `<Footer />`.

### `Sidebar.jsx`

Пример передачи данных в дочерний компонент и обёртки для колбэка:

```jsx
onClick={() => onCategoryClick(category.id)}
```

Обёртка нужна, чтобы «запомнить» id категории. Без неё при клике
наверх уйдёт событие, а не id.

### `CategoryItem.jsx`

Простой презентационный компонент. Ничего не хранит. Собирает класс
из базового и модификатора:

```jsx
className={`category-item ${isActive ? "active" : ""}`}
```

Если категория выбрана — получается `"category-item active"`.
Если нет — `"category-item "`. Лишний пробел безвреден.

### `StepIndicator.jsx`

Пример рендера списка с условием внутри:

```jsx
{
  index < steps.length - 1 && <div className="step-line"></div>;
}
```

Оператор `&&` — короткая форма «если условие, покажи элемент».
После последнего шага линия не рисуется.

### `ServicesList.jsx`

Пример условного рендера через тернарник:

```jsx
{services.length === 0 ? (
  <EmptyState message="В этой категории пока нет услуг" />
) : (
  services.map(...)
)}
```

Либо заглушка, либо список. Не оба сразу.

## Что можно взять в свой проект

- **Схему «состояние в одном месте, данные вниз, события вверх».**
- **Разбивку на компоненты по смыслу:** сайдбар, список, карточка.
- **Паттерн `<EmptyState />`** для случаев, когда данных нет.
- **Композицию `App`** — где корневой компонент собирает всю страницу
  из кусков.

## Что тут не реализовано

Это учебный пример, а не готовое приложение. Здесь нет:

- **Переходов** между экранами. Кнопки «Назад», «Выбрать» и «Войти»
  не работают. Клик по логотипу ничего не делает.
- **Сервера.** Данные захардкожены в `App.jsx`. Когда появится backend,
  массив заменится на `fetch`, а структура останется той же.
- **Валидации.** Проверок на пустые поля, ошибок загрузки и т.п. нет.
- **Роутера.** Страница одна, переключать нечего.
- **Заглушек загрузки.** `LoadingState` объявлен, но не используется —
  потому что данные приходят мгновенно.

Всё это — темы следующих лекций.
