# Страница выбора даты и времени на React с сервером

Учебное задание: добавить к своей странице календаря имитационный
сервер. Логика страницы не меняется — данные теперь приходят
не из локальных переменных, а из `/api/*`.

---

## Как запустить

Нужен **Node.js** версии 18 или выше.

```bash
npm install     # установить зависимости (один раз)
npm run dev     # запустить dev-сервер
```

Vite напишет адрес — обычно `http://localhost:3000`.
Откройте его в браузере.

---

## Что уже есть

- **`server/database.js`** — «база данных» с двумя наборами данных:
  - `today` — «сегодня» по мнению сервера;
  - `slotsEvenDay` / `slotsOddDay` — набор слотов для дней.
- **`server/server.js`** — плагин Vite, который перехватывает
  запросы к `/api/*` и отдаёт JSON. Работает как имитация backend.
- **`src/api.js`** — функции `fetchToday()` и `fetchSlots(date)`,
  которые делают запросы к серверу.
- **Подключение сервера** — уже в `vite.config.js`.

Ваша задача — использовать эти функции в своей странице.

---

## Эндпоинты

| Метод | URL                            | Что возвращает                     |
| ----- | ------------------------------ | ---------------------------------- |
| GET   | `/api/booking/today`           | `{ day, month, year }` — «сегодня» |
| GET   | `/api/slots?day=&month=&year=` | `{ date, slots }` — слоты на дату  |

`month` — 0-индексный (0 = январь, 9 = октябрь).

Проверить в браузере:

```
http://localhost:3000/api/booking/today
http://localhost:3000/api/slots?day=17&month=9&year=2026
http://localhost:3000/api/slots?day=18&month=9&year=2026
```

Обратите внимание: для 17-го и 18-го числа ответы разные. Так сделано,
чтобы было видно, что данные действительно приходят с сервера.

## Что нужно сделать

Логика страницы не меняется. Меняется только источник данных.

### 1. Загрузить «сегодня» при открытии страницы

Раньше `today` был захардкожен или брался из `new Date()`. Теперь его
нужно получить с сервера через `fetchToday()`.

Пока идёт запрос — покажите заглушку «Загрузка…». Если запрос упал —
сообщение об ошибке.

После загрузки `today` можно инициализировать состояние календаря:
какой месяц показывать, какой день выбран.

### 2. Загрузить слоты при смене дня

Раньше слоты были в локальном массиве. Теперь их нужно получать
через `fetchSlots(date)`, где `date` — это `{ day, month, year }`.

Запрос нужно делать:

- при первой загрузке `today` (когда стало известно, какой день выбран);
- при каждом клике на новый день.

Пока идут слоты — тоже показывайте заглушку.

### 3. Не забыть про состояния

У каждой загрузки — три состояния:

- **loading** — идёт запрос, показываем заглушку;
- **error** — запрос упал, показываем сообщение;
- **data** — данные пришли, рендерим.

Это относится и к `today`, и к слотам.

## Как устроены запросы

В `src/api.js` есть две функции:

```js
export async function fetchToday() {
  return request("/api/booking/today");
}

export async function fetchSlots(date) {
  const url = `/api/slots?day=${date.day}&month=${date.month}&year=${date.year}`;
  return request(url);
}
```

Обе возвращают Promise. В компоненте это выглядит так:

```js
const [today, setToday] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(() => {
  async function load() {
    try {
      setLoading(true);
      setError(null);
      const data = await fetchToday();
      setToday(data);
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }
  load();
}, []);
```

Пока `loading` — заглушка. Если `error` — сообщение. Иначе — данные.

## Что можно менять в сервере

### Данные

Всё лежит в `server/database.js`. Меняйте:

- **`today`** — например, поставьте реальную дату через `new Date()`.
  Или любую удобную для проверки. Если хотите, чтобы календарь
  всегда показывал один и тот же месяц — оставьте захардкоженным.
- **Слоты** — время и флаг `available`. Можно поставить другой
  набор. Главное — сохранить формат `{ time, available }`.

### Задержку

В `server/server.js` есть константа `DELAY_MS`:

```js
const DELAY_MS = 500;
```

Она имитирует сеть. Пока идёт задержка, на клиенте видно
состояние «Загрузка…». Поставьте `0`, если хотите мгновенные
ответы, или `1500`, чтобы загрузка была совсем заметной.

### Порт

В `vite.config.js`:

```js
server: {
  port: 3000,
}
```

Поменяйте на любой свободный, если `3000` занят.

## Если ваши данные отличаются

Пример сервера отдаёт `{ day, month, year }` и `{ time, available }`.
Если в вашем проекте структура другая — это нормально. Меняйте
`database.js` под свои нужды. Сервер отдаст то, что вы напишете.

Единственное, что важно сохранить — **разделение на два запроса**:

1. Отдельный эндпоинт для «сегодня».
2. Отдельный эндпоинт для слотов на дату.

Это правильно с точки зрения архитектуры: клиент грузит минимум
данных при открытии и запрашивает остальное по необходимости.

---

## Что НЕ нужно менять

- **`server/server.js`** — если вы не добавляете новых эндпоинтов,
  трогать его не надо. Он просто перехватывает запросы и отдаёт
  данные из `database.js`.
- **`vite.config.js`** — уже настроен. Меняйте только если порт
  занят или если нужно что-то ещё.
- **`src/api.js`** — можно дополнять новыми функциями, но уже
  имеющиеся трогать не нужно.

---

## Как проверить

1. Откройте DevTools → **Network** → фильтр `Fetch/XHR`.
2. При открытии страницы должен быть запрос `/api/booking/today`.
3. При клике по дню — запрос `/api/slots?...`.
4. У обоих должен быть статус **200**, ответ — JSON.
5. В **Console** ошибок быть не должно.

Проверьте три сценария:

1. **Открытие страницы.** Идёт запрос `today`, показывается заглушка,
   потом календарь отрисовывается на нужный месяц.
2. **Клик по другому дню.** Идёт запрос слотов, показывается заглушка,
   потом новые слоты.
3. **Ошибка сервера.** Остановите `npm run dev`, обновите страницу.
   Должна появиться не «бесконечная загрузка», а сообщение об ошибке.
